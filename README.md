# Palm Mind RAG API

A modular FastAPI backend for document ingestion, retrieval-augmented generation (RAG), conversational memory, and interview booking.

## Features

- **Document ingestion:** Upload PDF and TXT files through a REST API.
- **Configurable chunking:** Choose `recursive` or `fixed_size` chunking.
- **Embeddings:** Generate semantic embeddings with Sentence Transformers.
- **Vector search:** Store and retrieve document chunks using Qdrant.
- **Metadata persistence:** Store document and interview-booking records in SQLAlchemy-backed SQLite by default.
- **Custom RAG pipeline:** Retrieve relevant chunks and generate answers with Groq; source information is returned with answers.
- **Conversational memory:** Persist session messages in Redis.
- **Interview booking:** Collect candidate name, email, interview date and time; request explicit confirmation before saving the booking.
- **API documentation:** Interactive Swagger UI generated by FastAPI.

## Architecture

```text
PDF / TXT
    |
    v
Text Extraction
    |
    v
Chunking (recursive / fixed_size)
    |
    v
Sentence Transformer Embeddings
    |
    v
Qdrant Vector Database

Question
    |
    v
Qdrant Retrieval
    |
    v
Retrieved Context + Conversation
    |
    v
Groq LLM
    |
    v
Answer + Sources

Conversation History ---> Redis
Document Metadata ------> SQLite
Interview Bookings -----> SQLite
```

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/dipesh-bhattarai/palm-mind-rag.git
cd palm-mind-rag
```

### 2. Create and activate a virtual environment

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can invoke the environment's Python directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Install dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 3. Configure environment variables

Copy the example file:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and set your own Groq API key:

```dotenv
GROQ_API_KEY=your_groq_api_key_here
```

The application also supports these settings:

| Variable | Default | Purpose |
|---|---|---|
| `APP_NAME` | `Palm Mind RAG API` | API name |
| `APP_VERSION` | `1.0.0` | API version |
| `DEBUG` | `false` | Debug setting |
| `DATABASE_URL` | `sqlite:///./palm_mind.db` | SQLAlchemy database URL |
| `QDRANT_URL` | `http://localhost:6333` | Qdrant endpoint |
| `QDRANT_COLLECTION` | `documents` | Vector collection name |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis connection URL |
| `GROQ_API_KEY` | Empty | Groq API key |
| `EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Embedding model |

Do not commit `.env` or real API keys.

### 4. Start Qdrant and Redis

```powershell
docker compose up -d
```

Check container status:

```powershell
docker compose ps
```

Check Qdrant:

```powershell
Invoke-RestMethod http://localhost:6333/healthz
```

Check Redis:

```powershell
docker compose exec redis redis-cli ping
```

Redis should respond with `PONG`.

### 5. Start the API

From the project root, with the virtual environment activated:

```powershell
uvicorn app.main:app --reload
```

The API runs at `http://127.0.0.1:8000`.

Interactive API documentation:

- Swagger UI: `http://127.0.0.1:8000/docs`
- OpenAPI schema: `http://127.0.0.1:8000/openapi.json`
- Health endpoint: `http://127.0.0.1:8000/health`

## API Endpoints

### Health

`GET /health`

Checks API health.

### Upload a document

`POST /api/v1/documents/upload`

Upload a PDF or TXT document as multipart form data. Select a chunking strategy using `chunking_strategy`:

- `recursive`
- `fixed_size`

The response includes the document ID, filename, file type, selected strategy, chunk count, and processing status.

Example using Swagger UI:

1. Open `/docs`.
2. Expand `POST /api/v1/documents/upload`.
3. Click **Try it out**.
4. Select a PDF or TXT file and a chunking strategy.
5. Click **Execute**.

### Ask a question

`POST /api/v1/chat`

Example request:

```json
{
  "question": "Summarize the uploaded document.",
  "session_id": "demo-session-001",
  "document_id": "YOUR_UPLOADED_DOCUMENT_ID"
}
```

Use the document ID returned by the upload endpoint. Reuse a `session_id` to continue a conversation.

The response contains an answer, source chunks, a status, and booking information when relevant.

### Interview booking

Use `POST /api/v1/chat` for the booking conversation:

1. Ask to arrange an interview.
2. Provide the candidate's name.
3. Provide the email address.
4. Provide the preferred date in `YYYY-MM-DD` format.
5. Provide the time in `HH:MM` 24-hour format.
6. Review the proposed booking details.
7. Reply explicitly `yes` to submit, or `no` to reject/cancel.

A confirmed request is persisted in SQL with its booking ID and status. A `requested` booking is a recorded request, not confirmation by an interviewer.

## Testing

Run the automated tests:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = "1"
python -m pytest app/tests -v
```

The plugin-autoload setting can help avoid conflicts with unrelated globally installed pytest plugins in some Windows environments.

## Data and Persistence

- **Qdrant:** document chunk vectors and their payloads.
- **SQLite:** document metadata and interview booking records.
- **Redis:** conversation history and pending booking state.

The default SQLite database file and local Qdrant storage are runtime data and are excluded from Git.

## Notes

- The embedding model may download from Hugging Face the first time it is used.
- LLM-dependent endpoints require a valid Groq API key and network access.
- This repository provides a backend API; it does not include a frontend.
- The Docker Compose file starts Qdrant and Redis. The FastAPI application is started separately with Uvicorn.
